# Publishing AllotMint on Google Play (Trusted Web Activity)

AllotMint ships to Google Play as a **Trusted Web Activity (TWA)**: a thin
Android shell (`mobile/twa/`, package `com.allotmint.app`) that opens the
deployed PWA at `https://app.allotmint.io` full-screen in the user's Chrome.
There is no second UI codebase, so every web deploy updates the app's content
immediately. A new store release is only needed when the shell itself changes
(name, icon, colours, Android target).

Tracking issue: #11036. PWA groundwork: #11023.

What lives in the repo:

| Piece | Where |
| --- | --- |
| Android project (generated by Bubblewrap, hand edits listed in its README) | `mobile/twa/` |
| Signed `.aab` build, run on demand | `.github/workflows/android-twa.yml` |
| `/.well-known/assetlinks.json`, published when fingerprints are configured | `cdk/stacks/static_site_stack.py` |

The steps below are the ones only the account owner can do. Do them in order.

## 1. Create the upload key (once, on your own machine)

The upload key signs the bundles you upload. With Play App Signing (the
default), Google re-signs releases with its own app signing key, so a lost
upload key can be reset through Play support. Still, back it up, for example
in your password manager, and never commit it. `mobile/twa/.gitignore` ignores
`*.jks` and `*.keystore`.

```bash
keytool -genkeypair -v -keystore allotmint-upload.jks -alias upload \
  -keyalg RSA -keysize 2048 -validity 10000
```

## 2. Store the key as GitHub secrets

Encode the keystore and add these repository secrets (three required, one
optional) under **Settings → Secrets and variables → Actions → Secrets**:

| Secret | Value |
| --- | --- |
| `ANDROID_UPLOAD_KEYSTORE_BASE64` | the keystore, base64-encoded |
| `ANDROID_UPLOAD_KEYSTORE_PASSWORD` | the keystore password |
| `ANDROID_UPLOAD_KEY_PASSWORD` | the key password (same as the keystore password unless you chose otherwise) |
| `ANDROID_UPLOAD_KEY_ALIAS` | *optional*, defaults to `upload` |

```bash
# bash (Linux/macOS), with the GitHub CLI
base64 < allotmint-upload.jks | tr -d '\n' | gh secret set ANDROID_UPLOAD_KEYSTORE_BASE64 --repo leonarduk/allotmint
gh secret set ANDROID_UPLOAD_KEYSTORE_PASSWORD --repo leonarduk/allotmint
gh secret set ANDROID_UPLOAD_KEY_PASSWORD --repo leonarduk/allotmint
```

```powershell
# PowerShell (Windows)
[Convert]::ToBase64String([IO.File]::ReadAllBytes("allotmint-upload.jks")) |
  gh secret set ANDROID_UPLOAD_KEYSTORE_BASE64 --repo leonarduk/allotmint
gh secret set ANDROID_UPLOAD_KEYSTORE_PASSWORD --repo leonarduk/allotmint
gh secret set ANDROID_UPLOAD_KEY_PASSWORD --repo leonarduk/allotmint
```

## 3. Build the bundle

**Actions → Build Android TWA → Run workflow**, then enter a version name
(e.g. `1.0.0`). The workflow:

- fails straight away, naming any missing secret;
- builds `app-release.aab` with `versionCode` set to the run number, which
  only ever increases, as Play requires;
- rejects the build if the bundle is not actually signed;
- writes the **upload certificate SHA-256** to the run summary (you'll need it
  in step 5);
- uploads the `.aab` as a 30-day artifact.

## 4. Google Play Console

1. Create a developer account at <https://play.google.com/console> (one-off
   fee and identity verification).
2. **Create app**: name *AllotMint*, type *App*, *Free*.
3. Keep **Play App Signing** on (the default) when it asks.
4. Upload the `.aab` to a **Closed testing** track.
5. **New personal accounts must run that closed test with at least 12
   testers, opted in for 14 consecutive days, before they can apply for
   production access.** Recruit the testers before you need them.
6. Complete what Play requires before review:
   - **Store listing**: short and full description, the 512×512 icon
     (`mobile/twa/store_icon.png`), a 1024×500 feature graphic, and at least
     two phone screenshots.
   - **Privacy policy URL.**
   - **Data safety**: declare what the app actually collects. At minimum that's
     sign-in identity (email) and the portfolio data users enter, encrypted in
     transit. The TWA adds no collection beyond the website.
   - **App content**: content rating questionnaire, target audience, ads
     (none), and the **financial features** declaration. Answer it for what
     AllotMint actually does: it tracks and analyses portfolios and doesn't
     move money.

## 5. Verify the domain (removes the URL bar)

Until Android can verify that `app.allotmint.io` trusts the app, the TWA opens
with a browser URL bar. To fix that:

1. In Play Console, open **Test and release → App integrity → App signing**
   and copy the SHA-256 of the **App signing key certificate**. Include the
   upload certificate SHA-256 from the workflow summary too, so that builds
   signed with the upload key (e.g. sideloaded test builds) also verify.
2. Set them as a **repository variable** (not a secret, since fingerprints are
   public), comma-separated:

   ```bash
   gh variable set ANDROID_TWA_CERT_FINGERPRINTS --repo leonarduk/allotmint \
     --body "AA:BB:...:FF,11:22:...:99"
   ```

   Colons are optional and case doesn't matter. A malformed value fails CDK
   synth, so the `cdk-dry-run` check on the next PR catches typos.
3. Deploy as usual (push a `v*` tag). `StaticSiteStack` then publishes
   `/.well-known/assetlinks.json` with `Cache-Control: no-cache`.
4. Check it:

   ```bash
   curl -s https://app.allotmint.io/.well-known/assetlinks.json
   curl -s "https://digitalassetlinks.googleapis.com/v1/statements:list?source.web.site=https://app.allotmint.io&relation=delegate_permission/common.handle_all_urls"
   ```

   The second call should list `com.allotmint.app` with your fingerprints.
5. Reinstall the test build. It should open with no URL bar. If the URL bar
   persists, clear Chrome's data on the device and reopen. Android caches
   failed verifications.

## Releasing updates

- **Web changes** (features, fixes, styles) need no store release: the
  installed app loads the deployed site.
- **Shell changes** (app name, icon, colours, Android target/SDK updates)
  need a new build: run the workflow with a higher version name and upload the
  bundle to your track.
